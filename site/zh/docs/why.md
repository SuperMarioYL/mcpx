# 为什么需要 mcpx

## 痛点：N 个客户端 × 每个 5-6 步手工活

MCP server 的供给侧已经爆炸——光 `awesome-mcp-servers` 一个目录就有 90k+ star，Chrome DevTools 团队官方出品的 `chrome-devtools-mcp` 也有 45k+ star。找到一个好用的 server 越来越容易，但**装进客户端这一步还停留在手工时代**：

1. 查这个客户端的配置文件放在哪（每家路径都不同）；
2. 查它要求的 schema（每家形状也不同）;
3. 手改 JSON 或 TOML，祈祷没把别的键改坏；
4. 重启客户端；
5. 试一下，失败了回去改，再重启。

而且这套流程要**乘以你用的客户端数量**。同一个 `filesystem` server，在三个客户端里是三种写法：

- Claude Code：`~/.claude.json` 里的 `mcpServers.<name>`，要带 `"type": "stdio"`；
- Codex：`~/.codex/config.toml` 里的 `[mcp_servers.<name>]` TOML 表；
- Cursor：`~/.cursor/mcp.json` 里的 `mcpServers.<name>`，不带 `type`。

mcpx 把 `5-6 步 × N 客户端` 塌缩成一条命令：`mcpx add <server>`——探测、备份、按各家 schema 写入、逐一握手验证，最后告诉你 `3/3 clients ready`。

## 对比一：客户端自带命令（如 `claude mcp add`）

Claude Code 自带的 `claude mcp add` 确实好用——**但它只写 Claude Code 自己**。这不是偶然疏忽，而是结构性的：每家客户端厂商都不会去替竞品维护配置写入。你用几个客户端，就得学几套命令、跑几遍。

mcpx 站在所有客户端之外：一条命令写进**每一个**本机探测到的客户端。只用单一客户端的用户可能确实不需要它——mcpx 的价值集中在多客户端并存的工作流上，而多客户端并存正在成为常态。

## 对比二：手改配置文件

手改永远可行，但它是最容易出错的路径：改错 schema、误伤相邻键、忘记某个客户端、改完没验证。mcpx 的每一步都针对这些失败模式：

- **备份先行**——写之前先把原文件复制成时间戳备份；
- **只动一条**——合并的最小单位是单个 server 条目，你手工维护的其它配置纹丝不动；
- **写完就验证**——当场启动 server 跑一次 `initialize` + `tools/list` 握手，连不上立刻知道，而不是重启客户端后才发现。

## 对比三：目录与注册表式安装器

`awesome-mcp-servers` 这类目录回答「存在什么」，但找到之后的 clone / 配置 / 重启一步都不会少——目录不是安装器。Smithery、mcp-get 等注册表式方案偏向单点安装或云端注册表，部分能力需要账号。

mcpx 的差异是三点叠加：**(1) 写进每一个本机探测到的客户端**，而非只装一处；**(2) 装完跑握手冒烟测试**，证明 server 真的连得上；**(3) 全程本地、无账号、无云**。

| 能力 | mcpx | `claude mcp add` | 目录（awesome-mcp-servers） | Smithery / mcp-get |
| --- | :-: | :-: | :-: | :-: |
| 一条命令写进**所有**探测到的客户端 | ✓ | —（仅 Claude Code） | —（是目录） | 部分（单点 / 注册表） |
| 安装后握手冒烟测试 | ✓ | — | — | — |
| 备份 + 幂等合并（不动你的其它配置键） | ✓ | ✓ | 不适用 | 部分 |
| 本地、无账号、无云 | ✓ | ✓ | ✓ | 部分（偏云 / 注册表） |
| server 发现 / 目录规模 | 内置 8 个 | — | ✓ 90k★ 无可匹敌 | ✓ |

一句话：目录告诉你**存在什么**，各客户端的 `add` 只写**它自己**，mcpx **跨客户端写入并证明真的连上了**。

## 诚实的边界

mcpx 刻意不做的事，同样值得写清楚：

- **不托管 server**——它写的是本地启动配置，不是云服务；
- **不代装依赖**——内置目录只记启动命令，`npx` / `uvx` 在 server 首次运行时自行拉取包；
- **只管自己写的条目**——`remove` 只删除按名字命中的那一条，不清理你手工添加的其它内容；
- **不猜路径**——配置路径未在当前系统上确证的客户端一律跳过并明示，绝不猜测乱写。

核心的本地动作——探测、备份、跨客户端写入、握手——**开源、MIT 许可、无账号、永不收费**。面向团队的配置同步层在路线图上，但目前未实现、也不影响本地核心的任何能力。
